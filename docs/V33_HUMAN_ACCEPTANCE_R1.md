## Human UX finding: duplicate locale affordance

V3.3's global header switch is a real improvement because it makes language selection visible and route-preserving across all 16 paired surfaces.

However, on Russian surfaces that already render the existing `.ru-locale-bar`, V3.3 can create **two visible locale controls**:

1. the new global header switch generated by the postprocessor;
2. the existing page-level Russian locale bar.

Classification:

`HUMAN_UX_DUPLICATE_AFFORDANCE / NON_BLOCKING_FOR_BUILD / MUST_DECIDE_BEFORE_MERGE`

Preferred cleanup direction:

- retain the V3.3 global route-preserving header switch as the canonical locale control;
- suppress the old page-specific locale-switch affordance on pages where the global switch is present;
- retain any non-language value from the old RU bar (for example the Universe shortcut or product-layer status) only if it still earns its visual space.

Do not remove the old RU bar blindly before a fresh source/visual check because it also carries non-locale content on some Russian pages.
